# Mac mini 外置存储规划

本页是迁移计划。2026-11-07 已使用 `/Volumes/SuperAgentDockerData` 建立从 GitHub 获取的独立源码和受管 worktree；同盘已有专用 APFS 数据根。没有移动现网目录或 Docker 磁盘。最近观察外置可用约 42 GiB，Docker.raw 在内置盘的实际分配约 12.5 GiB；执行前必须重测，不能按逻辑上限或镜像显示大小估算释放量。

只读核对显示，该 APFS 卷是由外置 `/Volumes/My PSSD` 承载的磁盘映像，外层文件系统为 exFAT，承载盘当时约 1,719 GiB 可用。APFS 映像自身约 42 GiB 的余量才是本次项目写入上限。不能从外层余量推出 Docker 磁盘目标已合格；另行验证目标文件系统、容量和迁移/回退路径，不格式化现有盘。

| 资源 | 目标与顺序 | 验收及保护 |
| --- | --- | --- |
| 新 Git 工作区、离线测试日志及大型生成物 | 优先在外置建立新的 GitHub checkout/worktree，日志输出到专用外置目录 | 核对 remote、精确 SHA、任务与目录身份；不通过 Finder 或复制工作区覆盖另一份 Git 源码 |
| 已存在的本机工作树 | 已归并工作树走受管收尾；活跃工作在外置新建同候选工作树后有序交接 | 未提交文件、未归并提交、租约、原件和恢复证据先保全；未知占用不搬、不删 |
| 已知可再生的构建缓存和测试临时产物 | 新配置优先指向外置任务根，逐步退休旧缓存 | 保留宿主空间门。挂载仍由 VM 持有的缓存不能直接移动；先证明空闲、归属与可再生 |
| 已完成且获准归档的报告、可复算附件和证据副本 | 外置单独归档，与在线业务目录分开 | 复制后校验 SHA、引用、权限与可读性，再按原留存规则退休原副本；金融快照、Word/Excel 正式成果不改变资源语义 |
| Git 恢复备份与正在使用的回滚产物 | 现有位置先保留；外置备份位置另做受管兼容和恢复验证 | 不移动仍被回执引用的路径；两份有效恢复点和受保护旧点完整可恢复后才能退休重复副本 |
| Docker Desktop 整体磁盘 | 独立维护窗口，用 Docker Desktop 的 Disk image location 设置迁移到外置 APFS | 确认所有相关任务排空，保全业务卷与当前/上一镜像，核对外置容量和回退路径。不要手工移动 Docker.raw。见 [Docker 官方迁移说明](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/macfaqs/#how-do-i-move-the-disk-image-file) |
| 活跃数据库、凭据、当前服务和系统交换空间 | 不在本次迁移内 | 现网保留；专用卷继续按原只读/只写挂载约束。系统交换空间不手工搬或清 |

先把新产生的可再生工作空间放外置，再按所有者分批迁移可验证的旧产物。需要统一移动 Docker 磁盘时单独批准停机和目标路径；迁后核验镜像 digest、容器身份、卷内业务数据、服务健康、原来关闭的入口及本机实际释放量，验收后才处理旧副本。任何一门不明则保留现场。
