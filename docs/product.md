# 产品目标与验收

Super Agent 通过 Paperclip 统一管理个人跨项目任务。飞书负责输入和决策通知，GitHub 提供任务与交付事件，Codex 在限定工作区执行，项目适配层调用目标项目自己的验证和 Git 安全入口。

服务本人在不同项目中的研究、产品、设计、架构、编码、独立质量验证及运行维护。11个公司级岗位按任务绑定Native项目和工作区；共同基础能力、岗位默认专业组合与Chief的任务补充共同形成实际能力清单。岗位本身不固定某个业务仓库。

RWB是早期首个外部试点。2026-11-22起普通开发采用与直接Codex相同的项目授权，通过RWB原GitSafety、必需检查、独立评审及分支保护后可按登记范围合并，不再增加Agent身份的PR-only限制；生产部署仍按具体授权执行。Super Agent、Excel Relay及后续明确登记的仓库使用各自规则、验证环境和交付入口。新任务不改变旧M1任务、会话和历史归属。

## 早期试点验收合同

1. 本项目：Paperclip 执行一项操作指南文档任务，具有 Skills 加载证据、独立评审、适用本地检查、PR、同候选 CI、受保护合并及结果回传。
2. RWB：本人已绑定飞书验收会话发起任务，Paperclip 经隔离工作区新增受控任务交接说明，独立评审、RWB 必需检查通过后创建 PR，飞书回传；保持不合并、不部署。

两条都固定既有个人订阅、`gpt-6.1-sol` / `low`、独立开发与评审会话、每任务最多两轮修复。不设每日新任务数量硬上限，全局一个写者；原模型调用预算仍生效。输入不得扩大权限；未知远端结果先核对，不能重新调用模型或重复发布。

## 完成状态分层

源码交付记录提交、PR、评审和 CI；运行升级记录实际镜像、依赖、挂载和活动排空；业务验收记录任务全链及通知；资源收尾记录退休与回收。这四者独立，任一层受阻不抹去其他层证据，也不能用其他层 PASS 替代。

以上两条保留早期试点的原验收范围。通用11角色与跨项目能力按当前任务及[验收手册](acceptance-runbook.md)验证；长期无人值守与各项目生产发布使用各自明确授权，未覆盖行为保持未验收。
