# 用真实任务持续完善 Agent

业务交付与岗位完善在同一任务中推进。Chief 选用目标所需岗位，执行中出现方法、工具、交接或运行缺口时，在原任务中修复并保留证据。不先等待全部岗位材料完善，也不为了覆盖岗位而强行跑完12岗。

## 反馈及主责

有效反馈来自实际执行：触发条件、期望与实际行为、原任务和输入版本、run/操作或候选、脱敏错误和已有结果。修复者先读取现有实现与证据，确定主责及影响；旧失败不改写，结果未知先核对原操作。仅发现技能已分配、源码存在或工具返回版本，不能登记业务成功。

| 实际缺口 | 修改位置 | 主责与交接 |
| --- | --- | --- |
| 判断步骤、工作分支、交接或完成标准不清 | 本岗 AGENTS/SOP | 该专业岗修订，Chief 解决跨岗主责，独立评审核对 |
| 解释器、依赖、工具名、连接或动作证据缺失 | CAPABILITIES、工具接线及实际能力回执 | 对应专业岗定位；网络问题由 Network Engineer 牵头，接收方验证具体动作 |
| 派发、预算、权限执行、恢复或质量返修错误 | Super Agent 原运行代码和相关回归 | 技术执行者修复，独立 QA/代码评审复核 |
| 当前产品功能或业务规则错误 | 对应项目的原 Issue、分支与 PR | 项目执行岗位修复，沿该项目验证及交付规则 |

仓库路径、候选 SHA、临时运行状态与项目部署政策保留在项目上下文和任务证据；不复制成所有 Agent 的全局事实。职业规则不产生新的授权，也不改变当前项目最高动作。RWB 默认仍止于 PR；只有可信项目登记和任务操作许可同时满足，才有对应发布动作。

## 原任务修复和质量闭环

1. 固定原根/子任务、输入版本、原分支/PR、当前操作及累计调用数，读取现有失败和最新候选。
2. 主责执行者完成最小修复，按实际风险运行相关检查，保留旧候选及结果；避免另开同名任务或 PR 重置预算。
3. 独立 QA 只核对本轮非 QA 产物、精确候选和修复内容。`NEEDS_WORK` 提供定位、触发条件、影响及验收要求；由原执行岗修复，再由独立会话复核。成功运行的 QA 质量结论不是 Native 传输失败，不能用 `retry-now` 代替返修。
4. 新候选重新绑定必要的独评与项目检查，继续原 PR。文档方法、工具接线和业务改动按各自范围审查，不把 CI、角色配置发布或健康接口替代业务验收。
5. 汇总实际产物、质量结果、源交付、部署、业务验收及自有资源收尾。仍受阻则保留原任务可恢复进度，报告具体缺口及下一负责人。

默认原根最多6次外层角色调用；复杂任务必须有本人绑定的可信 `complex` 预算记录才可提高至12，保留已用次数。Chief 在计划中为最终 `summary`、必要的 `fix` 和独立复核预留调用；质量返修最多两轮。模型响应上限、原操作未知状态及全局单写继续按原运行合同约束，不能从文字计划提高预算。

## 能力证据不跨阶段推定

`role-capabilities.mjs` 保留现有完整 Skill 摘要和工具允许列表，另给出机器可读的 `evidence`：稳定的六个 `stages`，以及每个所选 Skill、允许工具的阶段状态。缺少对应证据时为 `NOT_RUN`。

| 阶段 | 可支持的结论 | 不能据此推定 |
| --- | --- | --- |
| assigned | 本run岗位/任务选择了能力 | 包已物化、工具可调用 |
| materialized | 实际文件、完整性与物化结果已核验 | 服务已连接 |
| discovered | 当前工具目录返回精确工具名 | 身份、权限或连接有效 |
| connected | 目标连接和适用身份/权限检查通过 | 目标读写、编译或转换成功 |
| action-tested | 所需具体动作在授权目标上执行并取得结果 | 用户任务满足验收 |
| business-accepted | 真实成果满足本任务验收并有独立质量结论 | 其他任务、格式或平台也已验证 |

当前能力解析器拥有的事实只包括分配和当前工具目录：`assigned=PASS`，实际目录中的允许工具可为 `discovered=PASS`，其余阶段保持 `NOT_RUN`。包索引/公司版本快照不等于本run已物化；目录中的 `connected` 等自述字段不提升证据阶段。物化、连接、实际动作和业务验收须引用其真实运行回执另行证明。

人读 CAPABILITIES 仅显示12位摘要前缀与文件位置；机器结果继续保留完整 `entrypointSha256`、`fileSetSha256`、`skillBundleSha256`，完整资产包索引保留逐文件清单，前缀不用于认证。`host.rwb_release` 是 DevOps 的岗位候选能力，不通过 Chief 或其他岗位组合继承；候选名称不代替可信项目元数据、受管操作身份和服务端校验。

## 发布及后续验证

稳定职业规则由 `bridge/team-roles.mjs`、能力事实由 `bridge/role-capabilities.mjs` 生成，24份 `assets/role-profiles/<role>/{AGENTS,CAPABILITIES}.md` 是同源可审查模板。按需工作分支直接放进实际 Native AGENTS 包；不能只链接在模型运行中不可读的仓库文档并声称已提供方法。本页说明维护协议，不是运行时额外依赖。

完成相关检查与独立评审后，经 PR、适用 CI 和既有发布器更新 Native Managed 材料。发布使用 CAS 检查当前版本，保留人工定制差异和历史；不直接覆盖在途材料。新材料只对下个 run 生效，当前 run 的固定快照不变。后续真实任务使用新方法或工具取得成功，才能补该范围的动作/业务证据；未使用岗位和未执行格式保持 `NOT_RUN`。
