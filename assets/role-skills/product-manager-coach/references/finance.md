# 金融投研软件：把可信度变成可验收的问题

这是产品设计与业务验收的提问清单，不是法规全文、投资建议或既定算法。只选与当前任务有关的问题。涉及法规适用时另查当前官方来源并确认适用对象。

## 从客户任务开始

明确本轮材料用于机构研究、渠道沟通、客户服务还是交易操作；实际使用者、资料接收者和复核者是谁。不要从“基金公司”推定所有用户权限、专业程度和使用方式相同。

教学示例可用“机构客户筛选、比较ETF并形成有来源的研究摘要”。它只能作为练习：哪些ETF、比较维度、客户为何需要摘要、可否外发、数据来源和使用频率仍须真实证据确认。

## 数据口径卡的必要问题

| 对象 | 需确认与验证的问题 |
|---|---|
| 来源与权限 | 数据由谁提供？授权允许显示、缓存、导出和外发到什么范围？未知时找谁确认？ |
| 对象标识 | 基金、份额类别、指数、市场和币种如何识别？同名或跨市场对象怎样避免混淆？ |
| 日期与时点 | 展示的是交易日、披露日还是取得时间？历史分析时该信息当时是否已经可得？ |
| 价格与收益 | 使用何种价格/净值、复权和分红处理？收益区间、费用、币种及年化方法由谁确认？ |
| 对比条件 | 区间、频率、基准、样本覆盖和风险口径是否一致？不一致时怎样解释或停止比较？ |
| 质量与更新 | 更新频率、缺失、延迟、异常和停牌等如何显示？过期数据是否仍允许生成结果？ |
| 输出与追溯 | 摘要和导出能否找到来源、数据截至时间、筛选条件、口径及版本？ |

不自行选择收益公式或授权政策。已有公式时用业务责任人确认的固定样本核对，记录允许的精度及舍入办法。当前只用样本数据时，把“教学演示可运行”与“生产结果通过”分开。

## 策略与回测

先确认产品提供展示、研究试算还是进一步决策支持。用如下问题明确业务规则及证据：

- 投资范围、信号、持仓约束、调仓时点、基准、费用与滑点的定义是什么？谁负责确认？
- 输入是否包含分析时点以后才能知道的信息？历史成分、退市或缺失样本怎样处理？
- 规则来自明确文档还是根据竞品曲线猜测？未知规则应保持未知，不能靠拟合外观证明复现。
- 是否有同输入、同规则的独立样本对照？训练/选择参数和验证样本怎样分开，哪些稳健性问题仍未验证？
- 结果是否同时解释观察期间、风险、回撤和限制？样本或回测收益不能写成客户可获得的未来收益。

“曲线和参考站不同”先收集同一对象、期间、来源、规则、费用与显示精度；将差异缩小到可核对的一层，再交给责任人处理。

## AI投研问答与研究摘要

先定义一项可评测任务，例如从授权研究材料中找依据并生成摘要，不直接把通用聊天作为产品目标。

业务评测至少考虑当前功能会遇到的以下情况：

| 情况 | 可观察的检查 |
|---|---|
| 有明确证据 | 回答是否回应任务，引用是否确实支持该结论，关键数值与日期是否一致？ |
| 无资料或过期资料 | 是否说明信息不足/截至日期，避免补造数字、来源和结论？ |
| 多来源冲突 | 是否展示冲突与各自时点，而非悄悄选一条当作已确认事实？ |
| 超出产品范围 | 是否说明边界并给合适下一步，而非冒充有权限的金融决策者？ |
| 权限不同 | 检索、回答和引用是否保持同一用户的访问范围？ |
| 资料中夹带指令 | 文档内容是否仅作为证据，不能改变用户目标、权限或引导泄露其他资料？ |
| 使用体验 | 可否核查出处、修正条件或反馈错误？任务成功、响应时延和成本怎样测量？ |

由业务方确认预期结果与可接受范围，保留评测集版本和真实运行结果。资料不足时先交付评测方案，不假称模型已达标。

## 对外交付与责任

研究材料、建议和交易能力的承诺边界应由业务确定。按实际功能明确结果复核者、对外使用范围、反馈处理和变更记录。涉及客户适当性、个人信息或金融服务规则的问题，核实具体适用范围；不因做图表页面就推定所有销售或交易规则均适用。
